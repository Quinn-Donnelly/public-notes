Kickoff

I want to make a game that is a small step up in difficulty on Tic Tac Toe Game. I learned better decoupling signal approaches from that one, so I want to start dipping my toe into simple physics. Breakout is a classic game of playing with physics in a rather simple system.

2025-10-13

I need to figure out the best way to get the bricks to break. To do this I need to actually cause breaking to happen then I can debate the finer points of how it’s doing it. Lets get a quick and dirty way working.

  • ? What is this ECS registry I keep coming across in mentions?

from testing today. The pattern that makes the most sense to me from a decoupling yet somewhat type safe option is the following:123

  1. Component registers itself with parent node (or scene root) with set_meta. Then it can also add the scene root node to a group.456
  2. The Component’s public functions are now the interface.
  3. Exterior objects can then check if something is in the group for that component. If yes get_meta then check it’s not null if so then they can call the public functions on it.7

Honestly right now the group may be unneeded. I think the component being null is enough right? Yea group isn’t needed.

2025-10-14

Today I’m going to work on the bounce mechanics for the ball. Ideally when it breaks the brick it bounces back. Then when it hits the paddle it bounces again.

Controlling it’s movement I’m assuming I’ll need to implement the position change and track velocity.

Remember that for out eventbus implementation we have to use @warning_ignore_start("unused_signal") and then @warning_ignore_restore("unused_signal") to avoid all the warnings about signal definitions not being used.1011

area_entered vs body_entered got me there for a bit.12

Ok I have a super rough implementation of it that just flips the velocity. Now I need to calculate the collision from center and use that to apply direction.

Alright doing that math on it the body position calculations likely not the direction. After some searches I can still use move_and_collide on a CharecterBody2D. That still gives me full control of physics.

Though i’ve made an error in my handling of collisions in Area2D there isn’t any reason I can’t implement the collisions in body_entered or area_entered the issue my angle math had was use of position instead of global_position.1314

I got the bouncing to work but the paddle has odd behavior. I think I need to move away from using normal and .bounce on it.

I want to take a look at using curves to make the bounce of the paddle have the x velocity I’m looking for. Instead of having to program the mathmatics into GDScript I should be able to use the curves to have the samplings from input → output that I’m looking for.

The feeling on hitting the ball now is pretty nice. I’ll now want to do more of the GameManager type stuff. I need a way to lose and win etc.
