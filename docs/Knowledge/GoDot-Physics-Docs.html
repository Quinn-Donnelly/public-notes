The bodies covered

  • Area2D
    • Zones of influence and detection1. They can change and override physics properties.
  • StaticBody2D
    • Bodies that won’t be moved by collisions or forces in physics engine but will participate in collisions. If you move their position property the physics engine won’t immediately update their collision information. Thus if you intend to move use AnimatableBody2D2
  • RigidBody2D
    • You don’t control them you apply forces and physics engine controls them3
    • They have a callback for you to integrate forces should you need to _integrate_forces(state: PhysicsDirectBodyState2D)
  • CharacterBody2D
    • Participates in physics collisions. It moves via the physics engine through methods for applying movement while respecting collision. You must determine how it handles / responds to collisions. 4 Moved by the developer through the physics engine.

move_and_collide - the base way to have a CharacterBody2D move_and_slide - a convince method that will allow the character to slide down walls. Note: it already applies delta to velocity in it’s calculation but doesn’t apply gravity (which must then apply delta)5

Putting in practice

You don’t multiply velocity by delta because the engine expects it’s value in pixels per second not by frame. Gravity / or acceleration forces in general, are in pixels per frame unit (how many pixels to add to velocity per frame)

RigidBodies

Don’t call look_at or set_transform every frame that will break the physics simulation. Using _integrate_forces instead.

Area2D

The key to use of an area is that you need to know about collisions but you don’t want physical interaction. This means I should likely refactor my bricks.

Area2D can influence object’s physics properties when they are in it’s area. By default it doesn’t do this but it can be turned on and has different modes. Combine will add it’s values to the objects values, Replace which will overwrite the objects physics values with the Area2D’s, and then it has two modes that allow for controlling the interaction with other Area2D (using priority) which determines if those do or don’t get processed.

CollisionObject2D is the abstract base class for 2D physics objects. It hold functions for managing the shape of collision objects, as well as callback methods for mouse events. Collision layer + masks are managed here as well.

CharecterBody2D

Physics engine won’t apply movement. You should not set position directly in a CharecterBody2D you should use the move_and_slide as well as move_and_collide functions, note you should do so in _physics_process.6
